# Platforms and release

Android is the first target. iOS is configured but, per `apps/phone-app/README.md`, not built yet (it needs a Mac). Linux desktop is for development only. There are no build flavours: the environment is chosen at build time with `--dart-define-from-file` ([configuration.md](configuration.md)).

## Android

Files: `android/app/build.gradle.kts`, `android/settings.gradle.kts`, `android/build.gradle.kts`, `android/gradle.properties`, `android/app/src/{main,debug,profile}/AndroidManifest.xml`.

### Build setup

| Item | Value |
|---|---|
| Application id / namespace | `com.anbessa.phone_app` |
| App label | `Anbessa` |
| `compileSdk`, `minSdk`, `targetSdk`, `ndkVersion` | from the Flutter Gradle plugin (`flutter.*`) |
| Version | from `pubspec.yaml` `version: 1.0.0+1` (`flutter.versionName` / `versionCode`) |
| Android Gradle Plugin | 9.0.1 (`settings.gradle.kts`) |
| Kotlin Gradle plugin | 2.3.20, declared `apply false`; the app module applies only `com.android.application` and the Flutter plugin |
| Gradle | 9.1.0 (`gradle-wrapper.properties`) |
| Java / Kotlin target | 17 |
| Core library desugaring | on, `com.android.tools:desugar_jdk_libs:2.1.5` (flutter_local_notifications uses `java.time` on older Android) |
| Release signing | the **debug** keys (`signingConfig = signingConfigs.getByName("debug")`, marked TODO) |
| Build output | `../../build` relative to `android/` (the root `build.gradle.kts` moves every project's build dir) |
| `MainActivity` | a plain `FlutterActivity` |

`android/gradle.properties`:

- `org.gradle.jvmargs=-Xmx8G -XX:MaxMetaspaceSize=4G -XX:ReservedCodeCacheSize=512m -XX:+HeapDumpOnOutOfMemoryError`
- `android.useAndroidX=true`
- `android.newDsl=false` (added by the Flutter template)
- `android.builtInKotlin=false`, with this comment: keep it false, because Flutter 3.44's Gradle plugin applies `kotlin-android` to every plugin that does not, which AGP refuses under built-in Kotlin. The "plugins that apply KGP: firebase_core" warning is a text match on firebase_core's opt-out branch; firebase_core 5.1+ already supports built-in Kotlin. Revisit when Flutter drops the flag.

`android/local.properties` is generated by Flutter with the SDK paths and must exist (`settings.gradle.kts` requires `flutter.sdk`).

### Permissions (`src/main/AndroidManifest.xml`)

| Permission | Why (manifest comments) |
|---|---|
| `INTERNET` | |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | pickup, driver position |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `WAKE_LOCK` | driver shift: geolocator keeps streaming through a location foreground service |
| `POST_NOTIFICATIONS`, `VIBRATE` | trip offers and payment prompts |
| `CAMERA` | document photos |

`ACCESS_BACKGROUND_LOCATION` is not declared; background updates rely on the foreground service started by geolocator (`GeolocatorSource`, `driverOnline` profile). The offer notification asks for a full-screen intent, but `USE_FULL_SCREEN_INTENT` is not declared in the manifest (it may be merged from a plugin; not checked).

### Foreground service

Started by geolocator while the driver is online (`ForegroundNotificationConfig` in `lib/core/location/location_source.dart`): title "Anbessa is online", text "Sharing your location with riders while you drive", wake lock on, icon `@mipmap/ic_launcher`. It stops when the position stream is cancelled (going offline, or the session ending on the server).

### Notification channels

Created at boot by `PlatformLocalNotifications.init()`: `offers` (Trip offers, max importance, sound) and `general` (default importance). See [architecture.md](architecture.md#local-notifications).

### Deep links and app links

On `MainActivity` (`launchMode="singleTop"`), with `flutter_deeplinking_enabled = true`:

- `anbessa://…` (VIEW, DEFAULT, BROWSABLE). The manifest comment gives `anbessa://trip/<id>` and `anbessa://pay/<tripId>` as examples.
- `https://app.anbessa.et/…` with `android:autoVerify="true"`. Verification needs `/.well-known/assetlinks.json` served on that host (comment and README); the host is hardcoded here, not taken from `APP_LINK_HOST`.

go_router receives the links; `/trip/:id`, `/pay/:id` and `/top-up/:id` are redirect routes ([architecture.md](architecture.md#deep-links)).

### Package visibility (`<queries>`)

`https` VIEW (payment pages), `tel` DIAL (SOS), `PROCESS_TEXT`. The navigation schemes the app opens (`google.navigation:`, `waze://`, `geo:`) are not listed; `openExternalNavigation` calls `launchUrl` directly and falls back down its list when one fails.

### Debug and profile manifests

- `src/debug/AndroidManifest.xml`: `INTERNET` and `android:usesCleartextTraffic="true"`, because the dev stack is plain `http`/`ws` (10.0.2.2 or a LAN IP). Release builds therefore need `https`/`wss` endpoints (as in `env/staging.json`).
- `src/profile/AndroidManifest.xml`: `INTERNET` only.

### Building an APK

```bash
cd apps/phone-app
flutter build apk --debug --dart-define-from-file=env/dev-emulator.json     # from the README
flutter build apk --release --dart-define-from-file=env/staging.json        # signed with the debug keys until a release config exists
```

Add `--dart-define=FIREBASE_API_KEY=… --dart-define=FIREBASE_APP_ID=… --dart-define=FIREBASE_PROJECT_ID=… --dart-define=FIREBASE_SENDER_ID=…` for push. No `google-services.json` is used; Firebase is initialised from these options in code. Release builds hide the dev sign-in panel whatever `DEV_LOGIN` says.

## iOS

Files: `ios/Runner/Info.plist`, `ios/Runner/AppDelegate.swift`, `ios/Runner.xcodeproj/project.pbxproj`.

| Item | Value |
|---|---|
| Bundle identifier | `com.anbessa.phoneApp` (differs from Android's `com.anbessa.phone_app`) |
| Deployment target | iOS 13.0 |
| Display name | Anbessa |
| App delegate | `FlutterAppDelegate` with `FlutterImplicitEngineDelegate`; scene-based (`SceneDelegate`) |
| Orientations | portrait and landscape left/right (iPad also upside down) |

Usage descriptions:

- `NSLocationWhenInUseUsageDescription` appears **twice** in `Info.plist` with different texts ("Drivers share their location…" and "Anbessa uses your location to set your pickup…").
- `NSLocationAlwaysAndWhenInUseUsageDescription`: keep sharing while online, even in the background.
- `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`: licence and vehicle documents.

Other keys: `UIBackgroundModes` `location` and `remote-notification`; `FlutterDeepLinkingEnabled`; URL scheme `anbessa`; `LSApplicationQueriesSchemes` `tel` and `https` (not `comgooglemaps` or `waze`, which `openExternalNavigation` tries on iOS). There is no entitlements file, so no associated domains for `https://app.anbessa.et` universal links and no push entitlement are configured in the repository.

## Linux desktop

`linux/CMakeLists.txt` (binary `phone_app`, application id `com.anbessa.phone_app`), `linux/runner/my_application.cc` (title "Anbessa", default window 1280 × 720).

- Location is always simulated (`Env.fakeLocationOn` is true on Linux) with the dev panel on the driver screens.
- If no keyring is available, a debug build keeps the session token in SharedPreferences (`insecure_session_token`); a release build fails.
- Local notifications, push, compass, the offer vibration and spoken guidance (flutter_tts) are no-ops off Android/iOS.
- `wakelock_plus` is pinned below 1.8.1 because newer versions need a dbus version `geolocator_linux` cannot use (`pubspec.yaml` comment).
- Run two windows to play rider and driver: `flutter run -d linux --dart-define-from-file=env/dev-host.json`.
